Privacy Policy

Last updated:

Folix is designed from first principles around local execution and radical user privacy. Folix is an open-source project by Yash Arya ().

1. Zero Server Uploads & Complete Local Isolation

When you open a PDF document in Folix, the file is read directly from your disk or device memory using standard HTML5 File APIs. The document bytes are parsed and rasterized exclusively in your browser session. No document pages, text, or metadata are ever uploaded to, stored on, or transmitted across our servers or any third-party clouds.

2. No Accounts, No Analytics, No Tracking Cookies

Folix does not require user accounts, logins, or authentication. Folix operates with zero tracking cookies, zero marketing trackers, and zero third-party telemetry scripts (no Google Analytics, no Facebook Pixels, no Hotjar, and no ad networks).

3. Local Device Storage Usage

To provide a seamless desktop-grade experience, Folix stores specific state variables solely within your browser's private storage (localStorage and IndexedDB):

  • Application Preferences: UI theme selection (Light, Sepia, Dark mode), zoom preferences, and consent dismissal state (folix.consent).
  • Reading State & Vector Annotations: Your last-read page number, handwritten pen/highlighter strokes, sticky notes, and text annotations are saved in localStorage, keyed to a cryptographic SHA-256 fingerprint of the document content rather than its filename.
  • Saved Signatures: If you create a reusable digital signature via the Draw or Type tool, its vector paths or render data are stored in your browser's local storage so you can easily reuse it.
  • Recent Documents (Optional): When the "Recent Files" feature is active, up to 12 previously opened documents (along with low-resolution thumbnail previews) are stored in your browser's private IndexedDB database. You can clear individual entries or the entire list at any time, or disable recent file caching from the main menu.

All stored data remains strictly on your device. Clearing your browser's site data or cache immediately erases all stored information.

4. On-Device Text Recognition (OCR)

Optical Character Recognition is powered by a WebAssembly build of Tesseract.js running in a local Web Worker. Scanned images are processed entirely on your CPU/GPU within the browser sandbox. Downloaded OCR language models (such as Italian or English) are cached in your local browser Cache API for offline use. No scanned pages, bitmap fragments, or recognized text are ever transmitted to any remote server.

5. Translation and External Services

  • On-Device AI Translation (Default): On Chromium-based browsers supporting native translation models (such as modern Chrome or Edge), translations run entirely on-device without any network traffic.
  • Optional MyMemory Fallback: If on-device translation models are unavailable and you explicitly check "Allow online translation", the selected text snippets are sent via HTTPS to the free MyMemory translation API (api.mymemory.translated.net). This service is strictly opt-in and disabled by default.
  • External Reference Lookups: The Dictionary button opens WordReference or Google Search in a separate browser tab, and the Google Translate link opens translate.google.com. These external navigations only occur upon explicit user interaction.
  • Static Web Hosting: The static application files are hosted via GitHub Pages, which logs standard HTTP request headers (such as IP address and user-agent) in accordance with GitHub's Global Privacy Policy.

6. Opening Remote Documents via URL

When opening a document via the ?file= query parameter, your browser executes a direct client-side fetch() request to retrieve the PDF from the provided remote URL. Folix acts only as the viewing client.
